
# Is PECO Okay?

Text-based low-bandwidth website for real-time information on the Philadelphia Power Grid.
View on the web at [https://www.IsPecoOkay.com/](https://www.ispecookay.com/).

## Development

### Setup

The default development interpreter is Python 3.14, selected by `.python-version`.

``` bash
# Set up the Python 3.14 environment from pyproject.toml and uv.lock.
uv sync
```

### Unit Tests

Run the unit tests with:

``` bash
uv run python -m unittest discover -s tests -v
```

### Actual Development

``` bash

# Build the website
./bin/build-site.sh

# Run FastAPI. The site and API share port 8000.
./bin/app-run.sh

#
# Start the cron script to fetch new records, purge old records, and
# periodically backup the database.
#
./bin/cron.sh

# Test the website and API
curl localhost:8000/
curl localhost:8000/about/
curl localhost:8000/peco
curl localhost:8000/peco/recent
```

The SQLite database stores each record's UTC collection time in a `timestamp`
column and assigns an auto-incrementing `id`. Main status records also store
PECO's reading time in an indexed `reading_timestamp` column. History windows
and trend baselines use that reading time. The purge command retains main status
records for eight days (providing headroom for a seven-day view) and raw archive
records for 365 days.
The database schema is created on first run and is not upgraded in place; when
changing the schema before deployment, start with a fresh database.

### Previewing with Fake Data

Running the fake-data script without arguments prints its help. To temporarily
replace the database with 10 days of randomized sample readings, run:

``` bash
uv run python bin/fake-data.py -g
```

This renames the current database to `db.sqlite-saved` (or appends `-saved` to
the configured `SQLITE_DATABASE_PATH`) before generating the sample database.
Each reading changes by no more than 10 outages and 100 customers affected
compared with the previous reading.
Restore the original database with:

``` bash
uv run python bin/fake-data.py -r
```

The long options `--generate` and `--restore` are also available. Run the
application with the same `SQLITE_DATABASE_PATH` setting used for generating
or restoring data. The generate command refuses to overwrite an existing saved
database.

### Working with Web Content

The HTML, JavaScript, and CSS are static files generated by [Hugo](https://gohugo.io/).
Hugo must build the site before FastAPI starts; FastAPI serves the generated files
from `hugo/public/` at `/`, alongside the API routes. The generated directory is
git-ignored, so build it locally before starting the application:

``` bash
./bin/build-site.sh
```

Hugo uses one configuration with the local app URL (`http://127.0.0.1:8000/`).
Hugo directory pages (such as `/about/`) are served directly by FastAPI.

### Running with Docker

Build the Hugo site and Docker image with:

``` bash
./bin/docker-build.sh
```

Run the application with:

``` bash
./bin/docker-run.sh
```

The image includes the AWS CLI used by the scheduled S3 database backups.
Docker loads environment variables from the repository's `env` file, including
`PECO_BACKUPS_S3_PREFIX`.
On normal startup, the container requires this setting and restores the most
recent compressed database backup from that S3 prefix to
`/app/${SQLITE_DATABASE_PATH}` (or `/app/db.sqlite` if the database path is unset).

The container serves the site and API on port 8000. SQLite data is stored in the
`peco-outage-data` Docker volume. To open a shell in the image instead of starting
the application, pass a command:

``` bash
./bin/docker-run.sh bash
```
